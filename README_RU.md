# sing-box-vps

[![CI](https://github.com/stillnotfree/sing-box-vps/actions/workflows/ci.yml/badge.svg)](https://github.com/stillnotfree/sing-box-vps/actions/workflows/ci.yml)

[English](README.md) · **Русский**

Минималистичный интерактивный установщик личного сервера sing-box на чистом
VPS. Сервер просто устанавливается, безопасно обновляется и управляется из
терминала без веб-панели.

## Возможности

- Устанавливает последнюю совместимую стабильную версию sing-box из официального подписанного репозитория.
- Поднимает VLESS + REALITY + Vision на TCP/443 и Hysteria2 + TLS на UDP/443.
- Не использует веб-панель, Docker, статистику, телеметрию и журналы подключений.

## Что потребуется

- Debian 13, Ubuntu 24.04 LTS или Ubuntu 26.04 LTS на `amd64`;
- от 1 vCPU, 1 ГБ оперативной памяти и 10 ГБ диска;
- публичный IPv4 и полноценный запуск через systemd;
- домен или поддомен с прямой `A`-записью на адрес VPS;
- настоящий адрес электронной почты для Let's Encrypt;
- **публичный** ключ OpenSSH одной строкой, например `ssh-ed25519 ...`;
- проверенный REALITY target с TLS 1.3 и HTTP/2.

Никогда не передавайте и не загружайте приватный SSH-ключ.

Откройте в firewall или security group провайдера:

| Протокол | Порт | Назначение |
| --- | ---: | --- |
| TCP | Текущий порт SSH | Администрирование |
| TCP | 80 | Проверка Let's Encrypt |
| TCP | 443 | VLESS + REALITY |
| UDP | 443 | Hysteria2 |
| TCP | 8443 | Приватные подписки |

DNS-запись должна вести прямо на VPS. Не включайте для неё CDN или DNS proxy и
не создавайте `AAAA`, если IPv6 не настроен намеренно.

## Установка

Подключитесь к VPS как `root` и выполните:

```bash
wget -qO vpn-install.sh https://github.com/stillnotfree/sing-box-vps/releases/latest/download/install-sing-box-server.sh && chmod 700 vpn-install.sh && ./vpn-install.sh install
```

Эта команда скачивает последний опубликованный GitHub release, а не изменяемый
`main`. Для установки точно проверенной версии замените `latest/download` на
`download/v1.0.11`; на странице текущего release также публикуется SHA-256
установщика. Перед запуском кода от root получите ожидаемый SHA-256 через
отдельно доверенный канал, проверьте файл локально командой
`sha256sum vpn-install.sh` и прочитайте скрипт. Контрольная сумма из того же
GitHub release полезна для проверки целостности, но не является независимым
trust anchor. Подробнее:
[docs/development.md](docs/development.md#clean-install-and-release-evidence).

Установщик запросит администратора, публичный SSH-ключ, IPv4 сервера, домен,
почту, текущий SSH-порт, REALITY target, страну VPS и fingerprint клиента.
Перед изменениями он покажет краткую сводку и спросит `[Y/n]`; достаточно
нажать Enter. Прерванную установку обычно можно продолжить той же командой.

Выбранный REALITY target проверяется сразу после ввода, если `openssl` и
`timeout` уже доступны. Иначе установщик явно отложит аудит до установки
зависимостей, но всё равно выполнит его до сохранения настроек. Ошибка TLS 1.3,
цепочки сертификата или ALPN h2 требует другого target. Ноль наблюдаемых
`NewSessionTicket` считается предпочтительным результатом именно для этой
эвристики; один или несколько tickets дают предупреждение, но target остаётся
пригодным и по умолчанию может быть оставлен. Режим `--yes` не может задавать
вопросы на этапе аудита: он только пропускает финальное подтверждение. Для
обычной установки с вопросами его указывать не нужно.

`vpn set-target DOMAIN` использует тот же аудит до начала транзакции. Target с
предупреждением comparison heuristic остаётся пригодным, но должен быть явно
принят до изменения настроек, конфигурации и подписок. Session tickets —
нормальное поведение TLS 1.3, а их количество не является security score.

## Структура исходников

Разработка ведётся в упорядоченных Bash-модулях каталога `src/`. Публичный
`install-sing-box-server.sh` — генерируемый автономный файл: на чистом VPS
по-прежнему не нужны Git и остальные файлы репозитория. После изменения
модулей пересоберите его командой:

```bash
scripts/build-standalone.sh
```

## Первый вход

Не закрывайте установочную SSH-сессию. В другом окне терминала войдите под
созданным администратором:

```bash
ssh ADMIN_USER@SERVER_IP
```

Первый успешный вход автоматически подтвердит firewall и включит SSH только по
ключу. Дополнительная команда завершения обычно не требуется.

Созданный пользователь — полноценный администратор с `NOPASSWD: ALL`. Поэтому
доступ к его приватному SSH-ключу даёт root через `sudo` без второго фактора.
`PermitRootLogin no` запрещает прямой вход как root, но не создаёт отдельную
границу привилегий после входа администратора.

Первый независимый клиент называется `default`. Показать его подписку, ссылки и
QR-коды:

```bash
vpn show default
```

Не публикуйте этот вывод: ссылки содержат данные доступа клиента.

## Команды

| Действие | Команда |
| --- | --- |
| Проверить состояние сервера | `vpn health` |
| Показать подробный отчёт с редактированием секретов | `vpn health -v` |
| Показать ограниченную отладочную диагностику | `vpn health --debug` |
| Проверить совместимость установки | `vpn check` |
| Показать клиентов | `vpn show` |
| Показать приватные ссылки и QR-коды | `vpn show NAME` |
| Добавить независимого клиента | `vpn add NAME` |
| Отозвать клиента | `vpn delete NAME --yes` |
| Безопасно обновить sing-box | `vpn update` |
| Обновить установленный менеджер VPN | `vpn self-update` |
| Проверить REALITY target | `vpn audit-target [DOMAIN]` |
| Сменить REALITY target | `vpn set-target DOMAIN` |
| Выбрать fingerprint | `vpn set-fingerprint` |
| Включить нативный Hysteria2/QUIC | `vpn set-obfs off` |
| Включить Salamander | `vpn set-obfs salamander` |
| Показать справку | `vpn help` |

Установленная команда `vpn` сама получает необходимые административные права,
поэтому добавлять `sudo` перед ней не нужно.

Известные ошибки `REALITY: processed invalid connection` считаются
неаутентифицированным входящим шумом, а не неисправностью сервера. Обычный и
подробный health-отчёты ими не засоряются; только debug показывает агрегаты за
30 минут и ограниченные примеры с удалёнными адресами и секретами.

`vpn health` проверяет только состояние на стороне сервера. Он всегда явно
показывает `Client-path reachability: NOT TESTED` и
`Provider firewall: UNKNOWN`; эти строки не меняют успешный exit code.
`--verbose` отдельно показывает версию sing-box, config check, service,
TCP/UDP-listeners, локальный nftables, локальную подписку, DNS/сертификаты,
сертификат, который фактически отдаёт nginx, и ограниченные этапы проверки
REALITY target по пути VPS -> target. Эти проверки не доказывают доступность по
пути клиент -> VPS и не определяют блокировку DPI.

Изменения target, fingerprint, обфускации, клиентов и sing-box проверяются и
применяются транзакционно. Адреса подписок не меняются, но после изменения
параметров подключения подписку на устройствах нужно обновить.

### Управление по SSH

Перед командой, которая может перезапустить sing-box (`vpn add`, `vpn delete`,
`vpn set-target`, `vpn set-fingerprint`, `vpn set-obfs`, `vpn update` или `vpn upgrade`), предпочтительно
добавьте на клиенте правило DIRECT для SSH-соединения с VPS. Если клиент умеет
маршрутизацию по порту назначения, используйте `VPS_IP:SSH_PORT`. Если на
уровне TUN/маршрутизации можно исключать только адреса, допустимо исключить
`VPS_IP/32`. Нельзя предполагать, что любой клиент поддерживает исключение по
паре адрес+порт.

Если текущее SSH-соединение нельзя положительно классифицировать как прямое,
команда сохранит проверенное изменение в состоянии `pending` и активирует его
после завершения именно исходного принятого SSH-транспорта. Повторное или
постороннее SSH-подключение не снимает и не продлевает это ожидание. Состояние
и итог доступны через `vpn health -v`. Удалённый клиент не считается отозванным
до завершения активации.

Пока отложенная операция ожидает активации, другие изменяющие состояние команды
отклоняются. Для кандидата сохраняются хэши управляемого состояния; если оно
изменилось, кандидат отбрасывается до активации. Если после перезагрузки или
исчезновения transient worker осталась orphan-задача, следующая privileged
операция зафиксирует безопасный failure и удалит устаревший кандидат; применить
его автоматически нельзя.

## Обновления системы

Обычные обновления ОС поддерживаются:

```bash
sudo apt update
sudo apt upgrade
vpn update
vpn health
```

Автоматически разрешены только security origins ОС, автоматическая перезагрузка
отключена. Пакет sing-box удерживается через APT и обновляется отдельно командой
`vpn update`: конфигурация проверяется, а при неудачном запуске может быть
восстановлен предыдущий пакет.

## Обновление установщика

Обновите установленный менеджер VPN из последнего обычного опубликованного
release проекта, затем проверьте итоговое управляемое состояние:

```bash
vpn self-update
vpn health
```

Команда скачивает `install-sing-box-server.sh` и опубликованный SHA-256 из
официального GitHub Release, сверяет байты и до подтверждения проверяет Bash-
синтаксис, принадлежность проекту и версию кандидата. Downgrade отклоняется; если
эта версия уже установлена, состояние не меняется. SHA-256 из того же GitHub
Release выявляет случайное повреждение или несовпадающие assets, но не является
независимым от GitHub trust anchor.

После подтверждения существующий транзакционный overlay upgrade выполняется в
одноразовом systemd unit независимо от SSH-сессии. Настройки, клиенты,
credentials, сертификаты, SSH и firewall сохраняются. sing-box может кратко
перезапуститься; если SSH идёт через этот же VPN, соединение может оборваться,
но обновление продолжится на сервере. Подключитесь снова и выполните
`vpn health`. Если прямой характер SSH-транспорта нельзя доказать, проверенный
management helper передаётся до возврата команды, а управляемый runtime и
state markers остаются на прежней версии; записывается pending outcome, и
совместимый с кандидатом worker применяет overlay один раз после завершения
сессии.

Для точно проверенного или офлайн-кандидата остаётся форма:

```bash
vpn self-update /path/to/install-sing-box-server.sh
```

`vpn self-update --yes` выбирает последний release без финального вопроса;
обычная политика неинтерактивных изменений сохраняется. Эта команда обновляет
установщик и управляемый overlay; `vpn update` по-прежнему отдельно обновляет
пакет sing-box.

## Что настраивает установщик

| Компонент | Настройка |
| --- | --- |
| Ядро | Совместимый стабильный sing-box из подписанного репозитория SagerNet |
| Основной протокол | VLESS + REALITY + Vision на TCP/443 |
| Резерв | Hysteria2 + TLS на UDP/443; нативный QUIC или Salamander |
| Клиенты | Независимые ключи, HTTPS-подписки, ссылки и QR-коды |
| SSH | Отдельный администратор, вход по ключу, отключение root/пароля |
| Firewall | Нативный nftables с временным автоматическим откатом |
| TLS | Сертификат Let's Encrypt и проверенное автоматическое продление |
| Сеть | BBR + `fq` при поддержке и умеренные пределы UDP-буферов |
| Диск | Swap 1 ГБ при поддержке и его отсутствии, журнал 200 МБ / 30 дней |
| Обновления | Только автоматические security updates без reboot; удерживаемые APT транзакционные обновления sing-box |

Установщик управляет только `table inet vpn_filter` и не очищает посторонние
таблицы nftables.

## Подписки

Каждый клиент получает непредсказуемый приватный URL подписки по HTTPS на
TCP/8443. Один URL отдаёт Base64-список VLESS/Hysteria2 либо готовый профиль
Mihomo в зависимости от `User-Agent`; формат Mihomo также доступен через
`/mihomo`. Маршрутизация, split tunneling и политика GeoIP остаются на стороне
клиента.

Совместимость и модель угроз описаны в
[docs/SUBSCRIPTIONS.md](docs/SUBSCRIPTIONS.md).

## Диагностика проблем подключения

1. Запустите `vpn health`, а при server-side ошибке — `vpn health -v`.
2. Если сервер исправен, проверьте тот же VPS/IP через другую сеть доступа.
3. Проверяйте REALITY TCP/443 и Hysteria2 UDP/443 отдельно: это независимые
   failure domains.
4. Проверьте SSH или другой трафик к тому же IP.
5. Сравните другой IP, VPS или хостера, не меняя настройки протокола.
6. Только после этого сравнивайте реализации клиентов и protocol-specific
   параметры.
7. Fingerprint — контролируемый A/B-параметр совместимости, а не гарантия
   обхода. Сначала проверяйте IP/path, TCP/443 и поведение клиента.
8. Исследуйте MTU только при подходящих симптомах timeout/stall; не меняйте
   default без воспроизведённого случая.

Работа Hysteria2 не доказывает, что REALITY, TCP/443 или IP не блокируются во
всех сетях. Успешный handshake также не доказывает пригодный tunnel. Основания
для этой модели кратко сохранены в
[docs/research/russia-network-findings.md](docs/research/russia-network-findings.md).

## Ограничения

- Ни один протокол, target или fingerprint не гарантирует обход любой фильтрации.
- Hysteria2 требует рабочего UDP и может замедляться в некоторых сетях.
- Установщик намеренно принимает только протестированную ветку sing-box 1.13.
- IPv6-профили, CDN-транспорты, port hopping, панели и статистика не настраиваются.
- Клиентская маршрутизация и TLS-фрагментация сервером не навязываются.
- Если `fq` настроен на уже работающем сервере, текущий интерфейс может сохранить
  `fq_codel` до пересоздания интерфейса или перезагрузки VPS.
- Ошибки invalid REALITY handshake могут появляться в сырых журналах и сами по
  себе не означают неисправность сервера или атаку.
- Проверяйте оба транспорта в реальных Wi-Fi и мобильных сетях.

## Примечание о разработке

Проект создан с помощью вайб-кодинга и ИИ, а затем проверен, протестирован и
доработан на реальных VPS с Debian и Ubuntu. Перед использованием на чужой
инфраструктуре прочитайте код и оцените компромиссы.

Эвристика `audit-target` основана на исследовании post-handshake поведения
TLS 1.3 и PoC [Aparecium](https://github.com/ban6cat6/aparecium) от ban6cat6,
распространяемом по лицензии MIT. Проект использует только узкую идею аудита
target и не включает кодовую базу Aparecium или её Go-зависимости.
